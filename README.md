# 筹备黑客松指北

面向线上黑客松组织者的筹备工作台：把赛制、时间、评审人力和各章待办放在一起，帮助主办方从报名准备推进到作品归档。

- **在线使用：** [筹备黑客松指北](https://online-hackathon-fieldbook.estherwongong.chatgpt.site)
- **公开源码：** [ESTHERWONGONG/hackathon-prep-guide](https://github.com/ESTHERWONGONG/hackathon-prep-guide)

## 功能

- 全局筹备时间轴与倒计时，可选择 24、48、72、96 小时制作周期、开赛时间和预计有效队伍数。
- 11 个筹备章节，每章展示待办、评分预设、规模测算与执行细则。任务由组织者手动确认，时间经过不会自动勾选完成。
- 专业评委／队伍互评支持 **60/40、70/30、50/50** 三种预设，联动规则、算例和模板导出。
- 每个独立赛道 **30 队及以下单轮评审，超过 30 队先海选，默认 12 队决赛**。
- 专业阅件时间、切换评分、开闭场和故障缓冲可调；路演每 8 队后休息 5 分钟，末队后不再加休息。
- 提供报名、签到、二开声明、成员承诺、提交、评分、申诉与回顾模板，以及国内外赛事参考来源。

本项目提供筹备计划与规则模板。正式活动的报名、作品收件、会议室和实际评分系统，仍需组织者按模板配置。

## 访客与账户

**访客**可以浏览规则、调整方案和下载模板，无需先登录。访客改动只在当前页面生效，不保存为账户计划；刷新或关闭页面后不会保留。未调整参数时，模板使用默认方案；调整后导出的模板随当前页面方案生成。

**登录用户**的开赛时间、制作周期、队伍规模、评分预设和任务完成状态保存到账户，之后可继续筹备。保存失败时页面会提示，不应把尚未保存的改动当作已经同步。

## 本地运行

需要 **Node.js 24 或更新版本**及 npm。本地预览使用 Node 内置的 SQLite 支持。

```bash
git clone https://github.com/ESTHERWONGONG/hackathon-prep-guide.git
cd hackathon-prep-guide
npm ci
npm run build
npm run dev
```

启动后访问 [本地预览](http://127.0.0.1:4173/)。修改源文件后，重新运行 `npm run build` 并刷新页面；必要时重启预览服务。

本地预览使用 `.sites-runtime/preview.sqlite`，以固定的 `local-preview` 身份模拟账户读写。首次启动会自动创建运行目录和本地数据表，不能依赖生产数据库副本。这个身份仅供 localhost 开发，不代表任何线上用户，也不会读取线上账户进度。

使用 `PREVIEW_GUEST=1 npm run dev` 可以预览匿名访客模式（本地不提供真实登录）。

## 文件结构

```text
dist/
  index.html          页面入口
  app.js              章节看板与交互
  content.js          规则、模板与算例渲染
  data.js             规则内容和参考来源
  prep.js             筹备状态、待办与时间轴界面
  prep-tasks.js       各章筹备任务
  schedule.js         时间节点计算
  planner.js          规模、人力与路演测算
  scoring.js          评分预设与公式
  store.js            计划读写接口
  style.css           基础样式
  theme.css           视觉主题
  templates/          静态模板文件
server/worker.mjs     静态资源与账户计划 API
db/schema.ts         计划数据表结构
drizzle/             数据库迁移
build.mjs            生成可部署的 Worker 与资源映射
preview.mjs          本地预览服务
```

`dist/` 中的前端文件也是本项目的可编辑源文件。`npm run build` 更新资源版本标识，并生成 `dist/server/index.js`；生成的服务端产物不需要提交到仓库。

## 部署与账户同步

网站继续使用现有托管，线上地址保持不变。**GitHub 用于公开和维护代码，向仓库推送提交不会自动发布到线上网站。** 发布需要另行构建并通过对应托管流程完成。本仓库也不把 GitHub Pages 配置为账户同步服务。

账户同步依赖两个运行条件：

1. **可信托管平台完成登录，并向服务端注入 `oai-authenticated-user-id`。** 该请求头必须由平台验证后设置，不能把来自任意客户端的同名请求头直接当作身份凭据。迁移到其他平台时，需要配套实现身份验证和可信网关边界。
2. **D1 数据库以 `DB` 绑定提供给 Worker。** 发布前按顺序应用 `drizzle/` 中的 SQL 迁移，建立 `prep_plans` 等所需结构；实际数据库绑定及平台配置由部署环境提供。当前线上来源是代码中的默认值，迁移时用 `SITE_ORIGIN` 指定新的允许来源。

`npm run db:generate` 根据 `db/schema.ts` 生成迁移文件，**不会自动把迁移应用到生产 D1**。本地 SQLite 与生产 D1 分开管理；生产迁移前应核对目标环境和已有迁移记录。

`/api/prep-plan` 按已验证的账户身份读取和更新计划。生产托管中的登录注入与数据库绑定不能由纯静态托管替代；本地预览中的模拟身份也不能用于生产认证。

## 公开内容边界

仓库公开应用源码、规则内容、模板及数据库结构，**不包含生产数据**。以下内容不进入公开仓库：

- `.openai/` 中的实际托管项目配置与身份信息。
- `.sites-runtime/`、运行中的 SQLite 文件及数据库导出。
- 账户进度、真实报名信息、作品提交或实际评分记录。
- 凭证、令牌、环境私密配置、日志和本机运行文件。
- 原开发目录的 Git 历史。

此公开仓库由经过筛选的源码建立，不携带原开发仓库历史。文档中的作品与表单示例是占位内容，赛事参考链接用于说明规则来源；历史赛事事实与本站建议分开标注。

## 规则使用说明

在筹备阶段可以切换评分和时间方案。正式报名开放前，应确定并发布本届规则版本；之后的重大变更需要通知参赛者并保留记录，不能把工作台中的即时调整自动视为已经生效的赛事规则。

公开源码不等于发布新的许可授权；本仓库暂未指定许可证。
