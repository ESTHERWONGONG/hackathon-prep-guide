# 筹备黑客松指北

面向黑客松组织者的筹备工作台：把赛制、时间、评审人力和各章待办放在一起，帮助主办方从报名准备推进到作品归档。

- **在线使用：** [筹备黑客松指北](https://online-hackathon-fieldbook.estherwongong.chatgpt.site)
- **公开源码：** [ESTHERWONGONG/hackathon-prep-guide](https://github.com/ESTHERWONGONG/hackathon-prep-guide)

## 功能

- 全局筹备时间轴与倒计时，可选择 24、48、72、96 小时制作周期、开赛时间和预计有效队伍数。
- 6 个可独立折叠的模块：赛制规划、网络搭建、赞助商合作、餐饮、会务、场地，共 21 个子章节。
- 原有 11 个赛制章节完整保留；新增 10 个执行章节和 30 项筹备待办。
- 支持线上／线下／混合形式。餐饮与场地的现场任务只在线下、混合模式计入进度，切换模式保留已勾选记录。任务由组织者手动确认，时间经过不会自动完成。
- 专业评委／队伍互评支持 **60/40、70/30、50/50** 三种预设，联动规则、算例和模板导出。
- 每个独立赛道 **30 队及以下单轮评审，超过 30 队先海选，默认 12 队决赛**。
- 专业阅件时间、切换评分、开闭场和故障缓冲可调；路演每 8 队后休息 5 分钟，末队后不再加休息。
- 顶部「生成方案」按当前参数、所选模块和待办状态导出可编辑 Word（.docx）或 PDF；可选执行细则和表单附录。全部适用待办完成且已设置开赛时间后生成完整方案，未完成时生成带缺项的筹备草稿。
- 提供报名、签到、二开声明、成员承诺、提交、评分、申诉与回顾模板，以及国内外赛事参考来源。

本项目提供筹备计划与规则模板。正式活动的报名、作品收件、会议室和实际评分系统，仍需组织者按模板配置。

## 访客与账户

**访客**可以选择线上／线下／混合形式，查看赛制总览与参考来源，并试算队伍规模。详细章节、待办、模板与方案导出需要登录。访客改动仅在当前页面生效；首次创建账户时会尝试带入当前试算参数。

支持 **邮箱＋密码注册、登录、退出和修改密码**。邮箱地址尚未验证，未接入邮件发送，因此暂不提供邮件验证码或密码找回。密码使用 Better Auth 的密码散列保存，会话通过 HttpOnly Cookie 管理，固定 7 天有效；注册和登录有服务端频率限制。原有 ChatGPT 登录继续可用，两种登录方式分别保存计划，不按同名邮箱自动合并。

**登录用户**的活动形式、开赛时间、制作周期、队伍规模、评分预设和任务完成状态保存到账户，之后可继续筹备。保存失败时页面会提示，不应把尚未保存的改动当作已经同步。

## 方案文件

点击顶部「生成方案」，填写文件标题，勾选本次包含的模块，再选择 Word 或 PDF。文件包含当前活动形式、周期与时间表、队伍规模、评分比例、评审人力、路演时长、所选模块清单，以及尚未完成的全局待办。侧栏折叠只是显示偏好，不影响文件范围；取消模块也不会让总进度变为完成。

下载使用一次配置快照。登录后会先等待当前改动保存，保存失败可重试。访客需先登录才能导出。方案内容从服务端已保存的账户计划生成，客户端仅提交标题、模块和附录选项。未在网站填写的实际赛道、奖项、场地、菜单、合作方或链接会保留为待补充，不会从勾选状态推断。进度包含赛后任务，因此开赛前也允许先下载草稿。

文件在浏览器本地生成，不调用第三方转换服务。文档组件按需加载；首次 PDF 下载另加载约 10.6 MB 中文字体，并在 PDF 中嵌入所用字形。Word 保留可编辑文字，使用本机中文字体回退，不同办公软件的分页可能略有变化。第三方组件的版本、来源和许可见 `dist/vendor/README.txt`。

## 本地运行

需要 **Node.js 24 或更新版本**及 npm。本地预览使用 Node 内置的 SQLite 支持。

```bash
git clone https://github.com/ESTHERWONGONG/hackathon-prep-guide.git
cd hackathon-prep-guide
npm ci
npm run build
npm run dev
```

启动后访问 [本地预览](http://127.0.0.1:4173/)。修改源文件后，重新运行 `npm run build` 并刷新页面；必要时重启预览服务。

本地预览默认匿名，使用 `.sites-runtime/preview.sqlite` 保存本地测试账户和计划。首次启动按顺序应用迁移，不能依赖生产数据库副本。可以用虚构的 `example.test` 邮箱测试注册登录，不会发送邮件。签名密钥只在本地进程内生成，重启服务后需重新登录。

使用 `PREVIEW_SIWC=1 npm run dev` 可模拟旧的 `local-preview` 平台身份。此开关只用于本机预览；服务会移除外部传入的身份头。

## 部署与账户同步

网站继续使用现有托管，线上地址保持不变。**GitHub 用于公开和维护代码，向仓库推送提交不会自动发布到线上网站。** 发布需要另行构建并通过对应托管流程完成。本仓库也不把 GitHub Pages 配置为账户同步服务。

账户同步依赖以下运行条件：

1. **邮箱账户需要 `BETTER_AUTH_SECRET` 服务端密钥。** 通过托管环境设置至少 32 字节高强度随机密钥，不能写入浏览器、代码或公开仓库。`.env.example` 只含变量名称。
2. **原有 ChatGPT 登录由可信托管平台完成，并向服务端注入 `oai-authenticated-user-id`。** 该请求头必须由平台验证后设置，不能把来自任意客户端的同名请求头直接当作身份凭据。迁移到其他平台时，需要配套实现身份验证和可信网关边界。
3. **D1 数据库以 `DB` 绑定提供给 Worker。** 发布前按顺序应用 `drizzle/` 中的 SQL 迁移，建立 `prep_plans` 等所需结构；实际数据库绑定及平台配置由部署环境提供。当前线上来源是代码中的默认值，迁移时用 `SITE_ORIGIN` 指定新的允许来源。

`npm run db:generate` 根据 `db/schema.ts` 生成迁移文件，**不会自动把迁移应用到生产 D1**。本地 SQLite 与生产 D1 分开管理；生产迁移前应核对目标环境和已有迁移记录。

`/api/prep-plan` 按已认证的账户身份读取和更新计划。邮箱账户使用带命名空间的随机用户 ID；未验证的邮箱不用于授权或合并旧账户。生产托管中的登录注入与数据库绑定不能由纯静态托管替代；本地预览中的模拟身份也不能用于生产认证。

## 功能权限配置

`config/features.json` 是权限的单一配置入口，服务端据此筛选内容、保护下载并检查计划读写和导出。每个功能支持 `public`（访客）、`member`（登录）、`paid`（授权）。当前 `billingEnabled: false`，所有非公开功能均向登录用户开放，**没有定价、结账、订阅或收款**。

后续可逐项设置章节、模板和导出权限。开启付费总开关后，`paid` 功能需服务端 `feature_entitlement` 中匹配的用户授权且未过期；客户端不能自行授予。接入支付前还需完成支付回调验签、授权发放／撤销与账务流程。个人计划读写、导出及模板下载不可配置为匿名操作，构建时会校验。

网站访问限制不等于内容保密：本仓库仍按要求公开指南源码，历史公开内容仍可从 GitHub 获得。网站只限制托管服务的访问及功能使用，不把公开源码当作收费内容的保密措施。

## 公开内容边界

仓库公开应用源码、规则内容、模板及数据库结构，**不包含生产数据**。以下内容不进入公开仓库：

- `.openai/` 中的实际托管项目配置与身份信息。
- `.sites-runtime/`、运行中的 SQLite 文件及数据库导出。
- 账户进度、真实报名信息、作品提交或实际评分记录。
- 凭证、令牌、环境私密配置、日志和本机运行文件。
- 原开发目录的 Git 历史。

此公开仓库由经过筛选的源码建立，不携带原开发仓库历史。文档中的作品与表单示例是占位内容，赛事参考链接用于说明规则来源；历史赛事事实与本站建议分开标注。

## 规则使用说明

在筹备阶段可以切换评分和时间方案。正式报名开放前，应确定并发布本届规则版本；之后的重大变更需要通知参赛者并保留记录，不能把工作台中的即时调整自动视为已经生效的赛事规则。

公开源码不等于发布新的许可授权；本仓库暂未指定许可证。
